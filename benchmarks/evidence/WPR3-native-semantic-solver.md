# WPR3 native semantic datatype solver evidence

This tranche adds the exact native bridge from dense IDs in
`DatatypeSemanticModelPayload` to complete datatype-component solving. It uses the
landed `NativeDataRange` public algebra and does not inspect or duplicate its private
DNF representation. It does not call Python or Java at runtime and does not alter the
older finite/complement-finite solver or datatype scheduler.

## Component contract

`SemanticDatatypeConstraintComponent` carries sorted dense variable IDs, positive or
negative dense range IDs, exact fixed `DataIdentity` values, equalities, inequalities,
minimum range cardinalities, and a `DependencySet` on every assertion. Compilation
validates all references and bounds, resolves every distinct dense range ID exactly
once, and retains that cache only in the returned immutable compiled component.

Solving performs the following deterministic pipeline:

1. collapse equality classes with the smallest variable as representative;
2. intersect all positive ranges and exact data-domain complements of negative ranges;
3. detect conflicting fixed values, empty intersections, fixed values outside their
   ranges, and insufficient range cardinality;
4. build canonical inequality edges, retaining the lexicographically smallest
   sufficient dependency support for duplicate edges;
5. eliminate a variable only when its exact range cardinality exceeds all active and
   fixed-neighbour exclusions;
6. solve the remaining finite core as an ordered list-colouring problem; and
7. reconstruct eliminated variables with `NativeDataRange::witness`, preferring exact
   concrete identities and otherwise returning family/digest/ordinal private symbolic
   certificates.

Equality aliases are compared only through `DataIdentity`, so integer/decimal lexical
aliases collapse while source-literal identity remains outside the solver. Every clash
returns a sufficient union of the participating assertion and equality supports;
participant IDs or unrelated branches are never added as backjump dependencies.

## Operation isolation and limits

`SemanticSolverLimits` is passed by value to each compile or solve call. Separate
positive ceilings cover variables, constraints, compiled range IDs, compile work,
solver work, and cancellation stride; `RangeWireLimits` continues to bound range DNF,
enumeration, regex, witness, value, and memory work. Local work counters are created
inside each call and discarded on return.

Compilation and solving mutate neither the semantic model nor the compiled component.
The focused tests interrupt a solve after several polls, force a solver-step failure,
then replay the same compiled component and obtain the byte-for-byte-equivalent result.
They also solve a baseline, a transient contradictory branch, and the baseline again;
the two baseline certificates are equal. This is the solver-side contract needed by a
transactional scheduler: cancellation and resource errors have no partial logical
state to roll back.

## Production Python oracle

`tools/datatypes/build_native_semantic_solver_fixture.py` uses only production Python
APIs: `compile_datatype_semantic_model`,
`compile_datatype_constraint_component`, and `DatatypeConstraintSolver`. The canonical
fixture contains 88 components: 24 crafted cases and 64 seeded generated finite cases.
It covers:

- finite Boolean, numeric, and mixed-family graph colouring;
- infinite integer and mixed string/numeric elimination;
- `owl:real` minus `owl:rational` private symbolic witnesses;
- positive and negative ranges and empty intersections;
- a three-level custom datatype alias with nested numeric complement;
- integer/decimal and alternate-integer lexical aliases;
- all six stable clash categories and exact dependency sets;
- cardinalities over explicit aliases and exact finite ranges;
- optimized-versus-exhaustive finite-domain SAT parity; and
- repeated deterministic solving and baseline/transient/baseline rollback order.

Regeneration check:

```text
  tools/datatypes/build_native_semantic_solver_fixture.py --check
```

`native/src/datatypes/mod.rs` and re-export the four functions and nine public types
listed in `semantic_solver.rs`. No scheduler or session mutation is required for this
