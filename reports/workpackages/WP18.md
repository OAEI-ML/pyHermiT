# WP18 — native structural compiler checkpoint

Status: implementation in progress; capability remains fail-closed
Prepared: 2026-07-21
Evidence revision: `f89b0bef332bc475c1ab8da85bfee33227ae1890`
Capability claim: none

## Outcome

The private encoded compiler now maps the retained pyowl-core schema into canonical
pyHermiT symbol, provenance, role, clause, and named-ABox fragments without paging the
same roots into Python objects. The implemented literal boundary preserves separate
source-literal spellings while deduplicating semantic values across every scalar-supported
literal family. Positive and negative data-property assertions, segmented composite
remapping, annotations, signed zero, lexical aliases, arbitrary-size numbers, binary
values, URI spelling, date/time offsets, and canonical XML fragments have exact
scalar/compiler manifest tests. The individual domain now also owns canonical anonymous
individuals used by OWL 2 DL-positive class, object-property, and data-property assertions,
including composite scope rebasing without misclassifying them as named individuals. Atomic
`ObjectComplementOf` assertions, subclass literals, equivalence/disjointness members,
property domain/range constraints, and key classes over named classes now retain their
canonical expression symbol, sparse entity signature, negated-concept predicate/fact,
signed clauses, and builtin totality/clash clauses.
Atomic `DataOneOf`, `DatatypeRestriction`, and `DataComplementOf` property ranges and
datatype-definition right-hand sides now receive the corresponding canonical data-range
expression symbols, signed predicates, data-sort totality/clash clauses, provenance, and
composite identifier remapping.
Named-individual `ObjectOneOf` class literals and their complements now receive canonical nominal
predicates, equality/inequality definitions, signed clauses or facts, and composite identifier
remapping across assertions, subclass/equivalence/disjointness axioms, property constraints, and
keys. Arbitrarily nested class and data complements over every supported atomic base reduce by
parity under the canonical depth and work budgets; unsupported complex or anonymous bases remain
deferred atomically.
Class and data intersections/unions that scalar normalization reduces to one supported atomic
literal now collapse natively through identity, absorbing, complement-parity, and duplicate rules.
This includes exact normalized disjoint-member ordering and forced-empty handling when distinct
source members collapse to the same class literal, plus composite identifier remapping.

This is a component checkpoint, not a completed structural compiler. The native
extension does not advertise `encoded-structural-compiler-v1`, and ordinary backend
negotiation cannot select this path.

## Implemented checkpoint surface

- strict schema-1 column decoding, hostile descriptor validation, retained-owner
  lifecycle checks, overlay selection, and composite slice merging;
- scalar-compatible entity, class-expression, named-and-anonymous individual,
  source-literal, and data-value domains for the implemented fragment;
- named class axioms, named object/data property domains and ranges, named datatype
  definitions, keys, named individual equality/inequality, and named or OWL 2 DL-permitted
  anonymous class/object/data assertions, subclass inclusions, class equivalences, and class
  disjointness, including atomic named-class complements and atomic named, enumerated,
  restricted, or complemented data literals in data-property ranges and datatype
  definitions, plus named-individual object nominals in every implemented class-literal position;
- bounded scalar-compatible reduction of class and data intersection/union expressions whose
  normalized result is already in the supported atomic literal fragment;
- object/data role signatures, inclusions, hierarchies, characteristics, regularity,
  automata, frozen role model, and role-clause compilation; and
- exact annotated provenance and canonical slice-local-to-global identifier remapping
  for the implemented roots.

The literal checkpoint covers the string and Boolean families; the complete integer,
decimal, rational, float, and double map; hex/base64 binary values; `xsd:anyURI`;
`xsd:dateTime` and `xsd:dateTimeStamp`; and `rdf:XMLLiteral`. Numeric digits/exponents,
decoded binary bytes, XML nodes/depth, total work, and owned bytes are bounded before
semantic publication. XML processing rejects DTD/entity declarations and uses a pinned,
audited Rust parser while preserving the scalar C14N identity contract. `rdfs:Literal`
remains intentionally unavailable as a direct lexical datatype because the scalar
compiler defines it only as the universal data range.

Anonymous individual keys and displays apply each slice's inner-to-outer scope maps before
domain merging. Their identifiers receive the scalar `owl:Thing` fact, but stay outside the
named-individual signature, output set, predicate, and builtin facts. Anonymous operands in
negative assertions and identity axioms remain atomically deferred because OWL 2 DL forbids
those positions.

Atomic complements participate in composite class-domain remapping without manufacturing
entity bindings for non-entity expressions. Each referenced named concept has paired positive
and negated predicates, a builtin clash clause, and a builtin `owl:Thing` totality disjunction.
Signed subclass literals preserve scalar provenance, composite remapping, and the scalar JSON
lexical ordering of multi-digit predicate identifiers. Scalar-trivial complement inclusions reduce
without leaking expression symbols. Atomic equivalence cycles retain the same signed edges and
grouped provenance as scalar, including composite remapping. Atomic disjointness members retain
their signed guard chain, canonical guard identity, annotated provenance, top/bottom reductions,
and composite remapping. Signed object-property domain/range, data-property domain, and key class
literals preserve exact constraint clauses, provenance grouping, and composite remapping.
Complements of `owl:Thing` and `owl:Nothing` normalize to the opposite builtin without expression
symbol leaks. Nested complements over supported named classes and named-individual nominals reduce
by parity to the base literal or innermost signed expression under bounded depth and work. The
normalized signed expression also supplies disjoint-guard identity, so guard hashes remain exact
across scalar comparison and composite remapping. Partially supported inclusions, equivalences,
disjointness and constraint roots, complements with complex bases, and other unsupported class
constructors remain wholly deferred without leaking partial symbols, predicates, clauses, or facts.

Atomic enumerations and datatype restrictions participate in exact composite remapping without
acquiring datatype entity bindings. Arbitrarily nested data complements over supported named,
enumerated, or restricted ranges reduce by parity under bounded depth and work. Positive and
negated data-range predicates receive builtin clash clauses and `rdfs:Literal`-guarded totality
disjunctions in the data sort. Annotated data-property ranges and datatype definitions preserve
scalar provenance and canonical ordering. The empty `DataComplementOf(rdfs:Literal)` range is also
exact. Data complements with unsupported complex bases remain wholly deferred without leaking
symbols, predicates, or clauses.

Named-individual object nominals retain canonical `ObjectOneOf` expression symbols and `Nominal`
predicates annotated by the remapped individual IDs. Their scalar-equivalent clauses define
membership through object equality; atomic complemented nominals additionally receive a
`NegatedNominal` predicate, object-inequality consequences, and the ordinary complement
totality/clash clauses. Assertions, subclass inclusions, equivalences, disjointness, object-property
domains/ranges, data-property domains, and keys share the same signed literal mapping. Annotated
duplicate roots preserve provenance, slice composition remaps both class and individual
identifiers. Tautological roots reduce, nested complements over named nominals normalize by parity,
and anonymous-member or partially supported roots defer without leaking nominal symbols or
predicates.

`ObjectIntersectionOf`, `ObjectUnionOf`, `DataIntersectionOf`, and `DataUnionOf` recursively remove
their top/bottom identity members, honor absorbing members, reduce complement parity, and collapse
normalized duplicates when the result is a single supported literal or builtin. No Boolean wrapper
symbol is published for these scalar-reduced roots. Disjoint members are re-sorted by their
normalized canonical keys before guard hashing; duplicate normalized members produce the scalar
forced-empty inclusion rather than a spurious guard. Multi-live Boolean expressions still require
generated definitions and remain atomically deferred.

## Open acceptance boundary

WP18 remains open. Remaining complex class-expression and data-range normalization/clausification,
complete root/profile/error coverage, direct permanent-session publication, cancellation
and allocation-failure campaigns, the full forced-native/verify matrix, installed
artifacts, and controlled performance/RSS gates are not yet complete. No public
capability or performance claim is justified until the complete work-package acceptance
matrix passes.
